# 前端实现保持型文案清理设计

## 背景

- 前端高风险开发阶段口径与内部实现视角文案已完成两轮清理。
- 当前仍残留少量更隐蔽的实现保持型说明，主要表现为：
  - “不改变已有计算和生成逻辑”
  - “按钮启停逻辑保持原有 server 校验”
  - “未运行分析时显示统一空状态提示”
  - “保持原有处理方式”
- 这类文案虽然不直接暴露研发阶段，但仍把实现细节或旧逻辑兼容关系带给最终用户，不符合用户可见文案边界。

## 目标

- 清理入口层与统计分析共享文案中的实现保持型表述。
- 将说明统一改为用户能理解的使用结果、输入要求或页面行为。
- 新增轻量守卫测试，阻断这类短语再次回流。
- 同步更新规范文档与测试索引。

## 非目标

- 不调整模块布局、按钮行为、建模逻辑或导出逻辑。
- 不改动 service 层错误消息与代码注释。
- 不对 `boxplot / heatmap / correlation_matrix` 开专项。

## 范围

### 本轮处理文件

- `modules/tables.R`
- `modules/statistical_analysis.R`
- `modules/common/stat_analysis_submodule_copy.R`

### 本轮处理位置

- `app_card_note()`
- 结果区 `note`
- 统计分析共享文案 helper

## 改写原则

- 将“保持原有逻辑/校验”改写为“用户何时可以执行、会看到什么结果”。
- 将“统一空状态提示”改写为“未运行时显示等待执行提示”等页面行为说明。
- 将“后续模型公式保持原有处理方式”改写为“按所选变量组成模型”这类业务语义说明。
- 保留真实边界，但不把 server、实现路径或兼容旧逻辑暴露给用户。

## 守卫测试

- 新增：
  - `tests/root/test_frontend_implementation_copy_guard.R`
- 只检查本轮目标文件中的高辨识度实现保持型短语，例如：
  - `不改变已有计算和生成逻辑`
  - `保持原有 server 校验`
  - `统一空状态提示`
  - `保持原有处理方式`
- 不做全文快照，只做轻量短语拦截。

## TDD 顺序

1. 先新增 `test_frontend_implementation_copy_guard.R` 并确认失败
2. 对目标文件做最小改写
3. 跑新增守卫、相关模块守卫、文档守卫
4. 同步更新规范文档与测试索引

## 文档同步

- `PROJECT_GUIDE.md`
  - 增补“实现保持型文案”禁止项与本轮范围
- `PROJECT_SPEC.md`
  - 记录该类文案边界
- `CODE_STYLE.md`
  - 补充实现保持型表述改写规则
- `TEST_GUIDE.md`
  - 登记新的实现保持型文案守卫

## 风险与缓解

- 风险：改写后丢失必要的执行条件说明。
- 缓解：保留“参数可用时可执行”“未运行时显示等待提示”等真实页面行为。
- 风险：守卫词过宽，误伤技术说明。
- 缓解：仅拦截少量高辨识度、明确属于用户可见文案的不当短语。
