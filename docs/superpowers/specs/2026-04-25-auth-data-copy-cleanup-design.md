# 账号入口与数据准备文案清理设计

## 背景

- 前端高风险开发阶段口径、内部实现视角文案和实现保持型文案已完成多轮清理。
- 当前账号入口、权限页与数据准备页仍残留一批偏开发阶段或结构视角的说明，例如：
  - “统一认证入口”
  - “后续新增账号相关入口也应沿用同一视觉规范”
  - “继续围绕邮箱身份扩展”
  - “当前页将...聚合展示，减少上下跳转”
  - “不改变原有加载能力”
- 这类表述会把页面内部组织方式、后续演进路线或研发口径直接暴露给用户。

## 目标

- 清理账号入口、权限管理、用户信息和数据准备页中的开发阶段与结构视角文案。
- 将说明统一改为“在这里能做什么 / 何时使用 / 会看到什么”的用户口径。
- 新增轻量守卫测试，拦截这批高辨识度短语回流。
- 同步更新规范文档与测试索引。

## 非目标

- 不调整登录、注册、找回密码、权限授权或数据加载逻辑。
- 不修改 service 层错误提示、数据库约束或认证流程。
- 不扩大到管理员页和数据库管理页的全部文案专项。

## 范围

### 本轮处理文件

- `modules/auth_manager.R`
- `modules/common/auth/auth_copy.R`
- `modules/data_preparation.R`
- `modules/account_access/permission_manager.R`
- `modules/account_access/user_profile.R`

### 本轮处理位置

- `subtitle`
- `app_card_note()`
- 局部说明文本 `div()` / `tags$small()`

## 改写原则

- 将“统一入口/统一承接”改写为页面实际用途说明。
- 将“后续扩展/后续新增”改写为当前可用能力或使用边界。
- 将“聚合展示/工作台布局/减少上下跳转”改写为用户可在此完成的操作。
- 将“原有加载能力/数据库侧结构”改写为数据是否写入、从哪里加载、对当前会话有何影响。

## 守卫测试

- 新增：
  - `tests/root/test_frontend_auth_data_copy_guard.R`
- 目标文件限定为本轮 5 个文件。
- 先拦截少量高辨识度短语，例如：
  - `统一认证入口`
  - `后续新增账号相关入口`
  - `继续围绕邮箱身份扩展`
  - `聚合展示`
  - `协作工作台`
  - `不改变原有加载能力`
  - `不改动数据库侧原有结构`

## TDD 顺序

1. 先新增 `test_frontend_auth_data_copy_guard.R` 并确认失败
2. 对目标文件做最小改写
3. 跑新增守卫和相关结构守卫
4. 同步更新规范文档与测试索引

## 文档同步

- `PROJECT_GUIDE.md`
- `PROJECT_SPEC.md`
- `CODE_STYLE.md`
- `TEST_GUIDE.md`

## 风险与缓解

- 风险：改写后丢失必要的权限或使用边界说明。
- 缓解：保留“谁能用 / 数据是否持久化 / 从何处加载”的事实信息。
- 风险：守卫词过宽，误伤正常业务说明。
- 缓解：仅使用本轮命中的高辨识度短语，不做语义泛化快照。
