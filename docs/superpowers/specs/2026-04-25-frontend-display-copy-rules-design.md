# 前端显示字段文案规则设计

## 背景

- 当前仓库中存在大量面向开发过程的前端可见文案，集中记录在 `dev_comments_to_cleanup.md`。
- 这些文案混入了“本轮只统一”“继续保留”“当前统一”“后续可接入”等开发阶段说明，不适合继续直接展示给最终用户。
- 本次改动只处理用户可见文案规则，不调整业务字段结构、计算逻辑、任务历史、导出链路或权限边界。

## 目标

- 将前端显示文案统一收口为用户可理解、可操作、可验证的说明。
- 移除开发过程口径，避免把重构范围、历史阶段和内部实现状态暴露到界面上。
- 保留必要的控件边界说明、结果含义说明和能力缺省说明。
- 为后续新增模块提供统一文案约束，并补充守卫测试防止旧口径回流。

## 非目标

- 不修改前端字段显隐、排序、字段名映射或结果 schema。
- 不调整统计分析、统计图形、表格或账号权限模块的业务语义。
- 不清理纯内部代码注释，除非该注释通过 UI 文案直接暴露给用户。

## 文案规则

### 允许保留的用户向文案

- 说明控件用途的文案，例如“这里控制 Y 轴标签显示格式，不会对原始变化值重新换算。”
- 说明结果内容的文案，例如“展示当前参数生成的交互式图形结果。”
- 说明功能边界的文案，例如“当前模块没有独立的参考线或阈值控件。”
- 说明固定约束的文案，例如固定导出尺寸、输入前置条件、缺省行为。

### 必须移除或改写的开发向口径

- “本轮只统一……不调整……”
- “继续保留……只统一……”
- “当前统一……不改变……”
- “继续沿用……不调整……”
- “后续如补充……可直接接入……”
- 任何直接暴露重构阶段、开发批次、临时占位、实现策略的说明。

### 改写原则

- 从“开发过程描述”改为“用户当前能做什么、看到什么、不能做什么”。
- 避免使用“本轮”“当前统一”“后续”等时间性词汇，除非它们表达的是产品长期有效的固定限制。
- 优先使用稳定陈述句，不描述内部重构意图。
- 同一类区域采用一致模板：
  - 参数区：描述该区域管理的输入范围。
  - 结果区：描述该页签展示的结果类型。
  - 导出区：描述当前支持的导出能力和固定约束。
  - 缺省功能区：直接说明未提供某类控件，不附带开发计划。

## 作用范围

- 按 `dev_comments_to_cleanup.md` 已列出的整份清单执行。
- 优先处理前端可见的 `subtitle`、`app_card_note`、`helpText`、`help_text`、`note` 等文案。
- 对 `# inline` 注释，仅处理那些被清单标记为应清理、且会影响用户展示规则理解的内容；纯内部实现说明默认不在本次范围。

## 测试策略

- 先新增一条文案守卫测试，覆盖开发向高风险词组，确保测试先失败。
- 测试至少拦截以下模式在用户可见文案中的回流：
  - “本轮只统一”
  - “继续保留”
  - “当前统一”
  - “继续沿用”
- 测试范围覆盖 `dev_comments_to_cleanup.md` 所列主要前端模块源码。
- 原有布局守卫测试保持不变，用于确认这次只改文案、不改结构。

## 文档同步

- `PROJECT_GUIDE.md` 增补“前端显示文案规则”约束与本次清理范围。
- `PROJECT_SPEC.md` 增补前端展示层文案边界，明确禁止暴露开发阶段口径。
- `TEST_GUIDE.md` 记录新增文案守卫测试入口与归类。

## 风险与缓解

- 风险：某些文案同时承载用户提示和开发阶段说明，机械删除会丢失必要边界。
- 缓解：优先改写为稳定的用户向说明，而不是简单删除。
- 风险：整份清单跨度大，容易出现不同模块替换口径不一致。
- 缓解：先以统一规则驱动替换，并用守卫测试约束禁用词组。
- 风险：部分 `inline` 注释属于内部实现提醒，不应误删。
- 缓解：本次默认只动用户可见文案与清单明确要求的内容。
