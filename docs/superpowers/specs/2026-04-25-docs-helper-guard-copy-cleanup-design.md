# 文档中的共享 helper 与守卫新增口径清理设计

## 背景

- 核心文档中的显性开发口径、进度口径和公共壳推进口径已清理多轮。
- `PROJECT_GUIDE.md`、`README.md` 与 `DEPLOYMENT_GUIDE.md` 中仍残留一批“新增/收口/补充”式过程描述，例如：
  - `当前新增共享文案源`
  - `现已收口到`
  - `当前补充了布局守卫`
  - `当前补充了 UI 守卫`
  - `当前补充 UI 守卫`
- 这类表述更像实施记录，而不是稳定的项目说明。

## 目标

- 将共享 copy helper、结果区/导出区 copy 源、smoke test 与布局守卫说明改为稳定事实表述。
- 保留 helper 覆盖范围、测试用途和运行前提。
- 新增轻量守卫测试，阻断这些短语回流。

## 非目标

- 不调整 helper 设计边界或测试执行条件。
- 不改动业务代码与测试实现。

## 范围

### 本轮处理文件

- `PROJECT_GUIDE.md`
- `README.md`
- `DEPLOYMENT_GUIDE.md`

### 本轮处理位置

- 共享文案源说明
- 结果区/导出区共享源说明
- smoke test 与布局守卫说明

## 改写原则

- 将“当前新增共享文案源”改为“使用共享文案源”。
- 将“现已收口到”改为“收口到”。
- 将“当前补充了”改为“提供”或“包含”。
- 将“当前补充 UI 守卫”改为“提供 UI 守卫”。

## 守卫测试

- 新增：
  - `tests/root/test_docs_helper_guard_copy_guard.R`
- 仅拦截本轮高辨识度短语：
  - `当前新增共享`
  - `现已收口到`
  - `当前补充了布局守卫`
  - `当前补充了 UI 守卫`
  - `当前补充 UI 守卫`
  - `当前补充了按需启用的`

## TDD 顺序

1. 新增 `test_docs_helper_guard_copy_guard.R` 并确认失败
2. 修改目标文档
