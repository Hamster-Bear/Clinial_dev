# 账号页与数据库锁定态灰区文案清理设计

## 背景

- 前端文案中的开发阶段口径、结构视角和实现保持型说明已完成多轮清理。
- 当前 `user_profile.R` 与 `database_manager.R` 锁定态中仍残留少量灰区表述，例如：
  - `集中到同一张功能卡片`
  - `改为登录后自助完成`
  - `仅保留基础密码修改，不扩展其它账号管理能力`
  - `在权限开放前`
- 这些文案虽然不算明显开发词，但仍带有页面结构或演进路径视角，不是最稳定的用户说明。

## 目标

- 清理账号页和数据库锁定态中的灰区结构/演进口径。
- 保留邮箱验证、换绑、改密和数据库权限边界的真实事实说明。
- 新增轻量守卫测试，阻断这批短语回流。
- 同步更新规范文档与测试索引。

## 非目标

- 不调整账号页 tab 结构、认证流程、数据库权限逻辑或锁定态跳转行为。
- 不修改 service 层消息与集成测试行为名称。

## 范围

### 本轮处理文件

- `modules/account_access/user_profile.R`
- `modules/database_manager.R`

### 本轮处理位置

- `app_card_note()`
- `profile-security-hint`
- 锁定态说明 `div()`

## 改写原则

- 将“集中到同一张功能卡片”改写为“可在这里完成哪些操作”。
- 将“改为登录后自助完成”改写为“登录后可直接完成”。
- 将“仅保留基础密码修改，不扩展其它账号管理能力”改写为“该区域用于修改密码”。
- 将“开放前”改写为“未开通时/权限未开放时”的当前状态说明。

## 守卫测试

- 新增：
  - `tests/root/test_frontend_user_lock_copy_guard.R`
- 仅检查本轮 2 个文件中的高辨识度短语：
  - `集中到同一张功能卡片`
  - `改为登录后自助完成`
  - `仅保留基础密码修改`
  - `不扩展其它账号管理能力`
  - `开放前`

## TDD 顺序

1. 新增 `test_frontend_user_lock_copy_guard.R` 并确认失败
2. 对目标文件做最小改写
3. 跑新增守卫与相关布局/边界守卫
4. 同步更新文档与测试索引

## 风险与缓解

- 风险：改写后弱化账号页和数据库锁定态的真实限制。
- 缓解：保留“登录后可直接验证”“仅用于当前会话分析”“不写入持久化数据空间”等事实边界。
