# README 与项目指南灰区文案清理设计

## 背景

- 前端运行页的开发阶段口径、结构视角与灰区说明已完成多轮清理。
- `README.md`、`PROJECT_GUIDE.md` 与 `DEPLOYMENT_GUIDE.md` 中仍残留少量进度口径，例如：
  - `当前显式提供`
  - `当前已改为更明显的`
  - `当前已抽成独立模块`
  - `当前已提供管理员操作入口`
  - `Owner 继续看到 workspace 协作权限管理卡`
- 这些表述更像开发过程描述，而不是稳定的产品或项目说明。

## 目标

- 清理三份核心文档中认证与管理员说明里的灰区进度口径。
- 将文案改为稳定的事实表述，不改变文档表达的真实边界。
- 新增轻量守卫测试，拦截这批短语回流。
- 同步更新测试契约中的旧预期文案。

## 非目标

- 不重写整份 README 或部署文档结构。
- 不改动业务代码、认证流程或部署逻辑。

## 范围

### 本轮处理文件

- `README.md`
- `PROJECT_GUIDE.md`
- `DEPLOYMENT_GUIDE.md`
- `tests/root/test_access_boundary_guard.R`

### 本轮处理位置

- 认证与管理员相关的边界说明段落
- 相关文档契约测试中的字符串预期

## 改写原则

- 将“当前显式提供”改为“提供”或“显示”。
- 将“当前已改为更明显的”改为“采用更明显的”。
- 将“当前已抽成独立模块”改为“由独立模块承载”。
- 将“当前已提供管理员操作入口”改为“管理员操作入口位于...”。
- 将“继续看到”改为“会看到”。

## 守卫测试

- 新增：
  - `tests/root/test_docs_grey_copy_guard.R`
- 仅检查三份文档中的高辨识度短语：
  - `当前显式提供`
  - `当前已改为更明显的`
  - `当前已抽成独立模块`

## TDD 顺序

1. 新增 `test_docs_grey_copy_guard.R` 并确认失败

3. 跑新增守卫、文档契约与边界守卫

## 风险与缓解

- 风险：改写后与现有文档守卫断言不一致。
- 缓解：同步更新 `test_access_boundary_guard.R` 中对应预期。
