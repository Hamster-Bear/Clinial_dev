# 管理员页与数据库管理页文案清理设计

## 背景

- 前端开发阶段口径、内部实现视角、实现保持型文案，以及账号入口与数据准备页中的结构视角文案，已完成多轮清理。
- `admin_manager.R` 与 `database_manager.R` 中仍残留少量高辨识度的结构视角说明，例如：
  - `系统管理入口`
  - `集中处理`
  - `按元信息统一筛查`
  - `当前卡片统一处理`
  - `数据空间工作台`
  - `统一完成整理与导入`
  - `阶段二将 ... 拆成不同区域`
- 这类文案会把页面内部组织方式、阶段性调整或管理结构直接暴露给最终用户。

## 目标

- 清理管理员页与数据库管理页中的结构视角和阶段性说明。
- 保留真实权限边界与操作结果说明，不改动管理员权限逻辑或数据库管理行为。
- 新增轻量守卫测试，拦截本轮高辨识度短语回流。
- 同步更新规范文档与测试索引。

## 非目标

- 不修改管理员页布局结构、统计卡逻辑、SMTP 探针、账号启停流程或数据库管理流程。
- 不扩大到服务层消息、通知文案或非用户可见代码注释。

## 范围

### 本轮处理文件

- `modules/admin_manager.R`
- `modules/database_manager.R`

### 本轮处理位置

- 主卡 `title`
- `subtitle`
- `app_card_note()`

## 改写原则

- 将“入口/工作台/集中处理”改写为页面当前能完成的具体管理动作。
- 将“统一筛查/统一处理”改写为“查看 / 筛选 / 管理 / 跟进”等用户动作表述。
- 将“阶段二”之类的阶段说明改写为当前页面如何组织功能区域。
- 保留“仅管理员可用”“不展示实际数据内容”“仅系统管理员开放”等真实权限边界。

## 守卫测试

- 新增：
  - `tests/root/test_frontend_admin_database_copy_guard.R`
- 仅检查本轮 2 个文件中的高辨识度短语，例如：
  - `系统管理入口`
  - `集中处理`
  - `统一筛查`
  - `统一排查与筛查`
  - `当前卡片统一处理`
  - `数据空间工作台`
  - `统一完成整理与导入`
  - `阶段二将`

## TDD 顺序

1. 新增 `test_frontend_admin_database_copy_guard.R` 并确认失败
2. 对目标文件做最小改写
3. 跑新增守卫与相关布局守卫
4. 同步更新项目文档与测试索引

## 文档同步

- `PROJECT_GUIDE.md`
- `PROJECT_SPEC.md`
- `CODE_STYLE.md`
- `TEST_GUIDE.md`

## 风险与缓解

- 风险：改写后弱化管理员权限边界提示。
- 缓解：保留“仅系统管理员可用”“不展示其他用户实际数据内容”等事实边界。
- 风险：布局守卫仍依赖旧标题文案。
- 缓解：同步更新相关守卫的预期字符串，仅调整文案，不改结构断言。
