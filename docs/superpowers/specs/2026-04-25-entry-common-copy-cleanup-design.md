# 入口层与公共模块内部实现视角文案清理设计

## 背景

- 前端高风险开发阶段口径已在核心统计图形模块中完成第一轮清理。
- 当前剩余的用户可见文案中，仍有一类不直接暴露研发阶段，但明显站在内部实现视角描述页面能力，例如：
  - “总入口内”
  - “公共筛选工作台复用”
  - “代码草稿”
  - “动态 UI”
  - “类型分支决定”
- 这类表述不会像“本轮不改”那样刺眼，但仍不够贴近最终用户理解方式。

## 目标

- 清理入口层与公共模块中仍带内部实现视角的用户文案。
- 将说明统一改为用户能直接理解的“这里做什么 / 会显示什么 / 如何使用”。
- 新增轻量守卫测试，阻断典型内部实现词再次回流。
- 同步更新规范文档与测试索引。

## 非目标

- 不调整模块布局、输入控件、执行逻辑或导出行为。
- 不扩大到次要图形模块专项整形。
- 不修改纯注释、server 内部变量名或服务层错误消息。

## 范围

### 本轮处理文件

- `modules/common/entry_copy.R`
- `modules/common/data_filter.R`
- `modules/task_history.R`
- `modules/tables.R`
- `modules/exploratory_analysis.R`
- `modules/statistical_graphics.R`
- `modules/statistical_analysis.R`

### 本轮处理位置

- `subtitle`
- `app_card_note()`
- `help_text`
- 结果区 `note`

### 本轮不处理位置

- 代码注释
- service 层报错
- 次要模块 `boxplot / heatmap / correlation_matrix`

## 改写原则

- 将“内部结构如何组织”改写为“用户在这里能完成什么”。
- 将“代码草稿”改写为“可复现代码”或“R 代码”。
- 将“动态 UI / 类型分支”改写为“会根据所选类型显示对应参数或结果”。
- 将“公共复用 / 总入口”改写为“本页 / 当前模块 / 当前分析 / 当前图形”。
- 保留真实使用边界，例如“默认折叠显示”“按用户保存”。

## 守卫测试

- 新增：
  - `tests/root/test_frontend_internal_jargon_guard.R`
- 只检查本轮目标文件中的高风险内部实现词，例如：
  - `工作台复用`
  - `总入口内`
  - `代码草稿`
  - `动态 UI`
  - `类型分支`
- 不做全文快照，只做轻量短语拦截。

## TDD 顺序

1. 先新增 `test_frontend_internal_jargon_guard.R` 并确认失败
2. 对目标文件做最小改写
3. 跑新增守卫、入口层守卫、公共模块守卫、文档守卫
4. 同步更新规范文档与测试索引

## 文档同步

- `PROJECT_GUIDE.md`
  - 增补“避免内部实现视角文案”的规则和本轮范围
- `PROJECT_SPEC.md`
  - 记录入口层与公共模块文案净化
- `CODE_STYLE.md`
  - 补充内部实现词改写规则
- `TEST_GUIDE.md`
  - 登记新的内部实现视角文案守卫

## 风险与缓解

- 风险：改写过度，丢失必要的使用边界。
- 缓解：保留“按用户保存”“默认折叠”“按当前类型显示”等事实信息。
- 风险：守卫词组过宽，误伤普通说明。
- 缓解：仅拦截少量高辨识度内部实现词，不用泛化词做断言。
