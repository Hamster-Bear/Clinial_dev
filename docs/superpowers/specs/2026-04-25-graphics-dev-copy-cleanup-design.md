# 核心统计图形模块开发口径清理设计

## 背景

- 入口层文案已收口到 `modules/common/entry_copy.R`。
- 统计分析子模块说明文案已收口到 `modules/common/stat_analysis_submodule_copy.R`。
- 统计图形结果区与导出卡的通用文案已分别收口到 `modules/common/graphics_result_copy.R` 和 `modules/common/graphics_export_copy.R`。
- 当前仍有少量用户可见说明残留开发阶段口径，主要集中在核心统计图形模块的 `helpText()`、`help_text =` 和少量模块内 `note =`。
- 这类表述会把“本轮只统一”“继续收纳”“暂不额外暴露”“不改绘图”等研发过程暴露给最终用户，不符合前端文案边界。

## 目标

- 清理核心统计图形模块中仍残留的开发阶段口径。
- 保留真实功能边界、模块限制和操作影响的事实性说明。
- 新增轻量守卫测试，阻断高风险开发短语回流到核心图形模块用户文案。
- 同步更新规范文档与测试索引。

## 非目标

- 不调整模块布局、输入项、导出逻辑或绘图算法。
- 不扩展共享 helper 的职责边界。
- 不对 `boxplot`、`heatmap`、`correlation_matrix` 做专项处理，它们继续作为跟随项。
- 不把所有图形模块的全部 `helpText()` 统一抽入共享源。

## 范围

### 本轮优先模块

- `modules/statistical_graphics/combo_plot.R`
- `modules/statistical_graphics/forest_plot.R`
- `modules/statistical_graphics/swimmer_plot.R`
- `modules/statistical_graphics/waterfall_plot.R`
- `modules/statistical_graphics/spider_plot.R`

### 本轮处理位置

- `helpText()`
- `help_text =`
- 少量仍残留开发过程口径的 `note =`

### 本轮不处理位置

- 已稳定的结果区共享结构
- 已稳定的导出卡共享结构
- 纯 server 端逻辑与计算说明
- 次要图形模块的专项整形

## 方案对比

### 方案 A：只清理核心图形模块中的开发阶段说明

- 优点：用户感知强，改动小，易于验证。
- 缺点：入口与公共模块的少量残留口径后续仍需继续处理。
- 结论：采用本方案。

### 方案 B：先清理入口与公共模块说明

- 优点：文件更少，修改更快。
- 缺点：图形模块中的明显开发口径仍会继续暴露给用户。

### 方案 C：核心图形模块与入口/公共模块一起做

- 优点：一次更彻底。
- 缺点：范围明显扩大，不利于按小批次稳定推进。

## 设计

### 1. 改写原则

- 保留事实性边界：
  - 例如“没有独立交互图”“没有轨道变量”“没有参考线控件”这类客观限制可以保留。
- 移除开发过程表述：
  - 例如“本轮”“当前统一”“继续收纳”“暂不额外暴露”“不改绘图”“不改导出”“优先收口”等。
- 统一改写为稳定说明：
  - 只描述当前可以设置什么、不会影响什么、当前缺少什么。

### 2. 典型改写方向

- `combo_plot`
  - 将“高动态图层参数继续在图层样式页签中维护”改为“高动态图层参数在图层样式页签中设置”。
  - 将“本轮优先收口 UI 格局与任务历史恢复，不改绘图语义”改为“标题默认按所选图层组合生成，可直接在图层样式中调整其他显示项”。
  - 将“暂不额外暴露统一坐标格式控件”改为“坐标格式随当前图层类型和映射方式显示”之类的事实性说明。
  - 将“本轮不改绘图与导出算法”改为固定画布的用户向提示。

### 3. 模块专属事实可保留

- `forest_plot` 的“当前没有独立交互图结果”属于真实功能边界，可保留这一事实，但要去掉“本轮仅统一结果区结构，不改绘图实现”。
- `swimmer_plot`、`waterfall_plot`、`spider_plot` 中“没有独立分面变量”“没有参考线或阈值控件”等事实说明可保留，但应去掉“统一收纳”“当前页签未提供业务阈值线设置”这类过程型口径。

### 4. 守卫测试

- 新增测试：
  - `tests/statistical_graphics/ui/test_graphics_dev_copy_guard.R`
- 守卫目标：
  - 仅检查本轮优先模块。
  - 拦截高风险开发短语，例如：
    - `本轮`
    - `统一收纳`
    - `暂不额外暴露`
    - `不改绘图`
    - `不改导出`
    - `继续在`
    - `继续收纳`
    - `优先收口`
- 守卫不做全文快照，只校验高风险词组是否仍出现在用户可见文案相关文件中。

### 5. TDD 顺序

1. 先新增 `test_graphics_dev_copy_guard.R` 并确认失败
2. 对五个核心图形模块做最小改写
3. 保持模块专属事实性边界不变，只去掉开发过程口径
4. 跑新增守卫、现有图形文案守卫、布局守卫和文档守卫
5. 同步更新文档与测试索引

## 风险与缓解

- 风险：误删真实功能边界提示。
- 缓解：保留客观限制事实，只移除研发过程语气。
- 风险：守卫词组过宽导致误报。
- 缓解：仅拦截最典型的开发过程短语，不用宽泛的“当前”做断言。
- 风险：继续扩大到次要模块会让本轮范围失控。
- 缓解：`boxplot`、`heatmap`、`correlation_matrix` 维持跟随项策略，不单独纳入本轮。
